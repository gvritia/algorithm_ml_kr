# Текущий контроль 5–6: классификация качества красного вина

Решение задания из [исходного ноутбука](Текущий%20контроль%205-6.ipynb) находится в отдельном файле: **[Текущий контроль 5-6 (реализация).ipynb](Текущий%20контроль%205-6%20(реализация).ipynb)**. Исходный пример с ирисами не изменён.

## Задача

По 11 физико-химическим признакам из `winequality-red.csv` предсказать исходную оценку `quality` методом $k$ ближайших соседей (kNN). В данных представлены шесть оценок: 3, 4, 5, 6, 7 и 8. Это **многоклассовая классификация**. В работе 3–4 оценка превращалась в два класса; здесь она остаётся исходной.

3. Запустите все ячейки по порядку из корня проекта. CSV должен лежать рядом с ноутбуком; в этом проекте он уже находится там. Упоминание папки `data` в исходном задании не соответствует текущему расположению файла.

Для запуска через терминал при необходимости установите зависимости:

```powershell
python -m pip install numpy pandas matplotlib scikit-learn jupyter
jupyter notebook "Текущий контроль 5-6 (реализация).ipynb"
```

## Ход решения

1. Загружаются данные и удаляются 240 полностью повторяющихся строк. Если оставить повторы, одно и то же вино может попасть и в обучение, и в тест и завысить оценку качества.
2. 1359 уникальных вин делятся на обучение (1019) и тест (340) с сохранением пропорций оценок (`stratify=y`, `random_state=42`).
3. `StandardScaler` и `KNeighborsClassifier` объединены в `Pipeline`. Для признака $j$ применяется $x'_j=(x_j-\mu_j)/s_j$; параметры масштабирования вычисляются только на обучающих данных соответствующего разбиения.
4. Число соседей $k\in\{1,3,\ldots,31\}$ выбирается пятиблочной кросс-валидацией на обучении по **macro F1**. Тестовая часть не участвует в подборе.
5. На тесте считаются accuracy, macro F1, weighted F1, отчёт по каждому классу и матрица ошибок. Для сравнения показана модель, которая всегда выбирает самый частый класс.

kNN использует евклидово расстояние между стандартизованными признаками:

$$d(\mathbf{x}',\mathbf{z}')=\sqrt{\sum_{j=1}^{11}(x'_j-z'_j)^2}.$$

Ответ — наиболее частая оценка среди $k$ ближайших обучающих вин. В матрице ошибок **строка** обозначает реальную оценку, **столбец** — предсказанную.

## Полученные результаты

При указанном разбиении и версиях библиотек, использованных для проверки, на кросс-валидации выбрано $k=1$. На 340 тестовых винах:

| Модель | Accuracy | Macro F1 |
|---|---:|---:|
| Всегда самый частый класс | 0,424 | 0,099 |
| kNN | 0,524 | 0,296 |

kNN правильно предсказал 178 оценок. Самые частые ошибки — путаница между оценками 5 и 6: 49 вин класса 5 отнесены к классу 6 и 41 вино класса 6 — к классу 5. Редкие оценки 3 и 8 на тесте не распознаны. Поэтому общая accuracy выше базового правила, но качество по отдельным классам неравномерно. Для редких оценок мало обучающих примеров, и их оценка на тесте особенно нестабильна.

# Текущий контроль 7–8: логистическая регрессия для страхового риска

Решение задания из [исходного ноутбука](Текущий%20контроль%207-8.ipynb) находится в файле **[Текущий контроль 7-8 (реализация).ipynb](Текущий%20контроль%207-8%20(реализация).ipynb)**. Исходный пример не изменён.

## Задача и файлы

По 28 полям договора из `insclass_train.csv` нужно предсказывать бинарный `target`: 1 — рисковый договор, 0 — нерисковый. Ноутбук сравнивает два самостоятельно реализованных способа обучения логистической регрессии:

1. градиентный **подъём** для максимизации логарифмического правдоподобия (`LL`);
2. градиентный **спуск** для минимизации кросс-энтропии (`CE`).

В условии также требуется прогноз для 22 624 строк `insclass_test.csv`. **Этого файла в проекте пока нет**, поэтому фактические прогнозы для него сейчас получить нельзя. Вместо него 20% строк `insclass_train.csv` отделены до обучения и используются для честной проверки. Ноутбук сохраняет результаты этой проверки в `insclass_validation_predictions.csv`: номер исходной строки, настоящий `target`, прогноз и оценку вероятности риска. Последняя ячейка отдельно проверяет наличие официального тестового файла и, когда он появится рядом с ноутбуком, создаст `insclass_test_predictions.csv` со столбцом `target` в исходном порядке строк.

## Как запустить

Откройте `Текущий контроль 7-8 (реализация).ipynb` в PyCharm или Jupyter и запустите все ячейки из корня проекта. Нужны `numpy`, `pandas`, `scipy`, `matplotlib`, `scikit-learn`, `IPython` и `ipykernel`. При необходимости:

```powershell
python -m pip install numpy pandas scipy matplotlib scikit-learn jupyter
jupyter notebook "Текущий контроль 7-8 (реализация).ipynb"
```

## Что делает ноутбук

- Загружает 151 406 размеченных договоров. Исключает постоянный `variable_3` и почти пустой `variable_15` (лишь 13 заполненных значений).
- Откладывает 20% договоров со стратификацией (`random_state=42`). Медианы, масштабирование и словари категорий обучаются только на оставшихся 80%.
- Числовые пропуски заменяет медианами и отмечает индикаторами. Категории кодирует one-hot; итоговая матрица разреженная.
- Для обоих методов использует одинаковые нулевые начальные коэффициенты, 250 шагов, скорость обучения 0,3, L2-коэффициент 0,001 и одинаковые веса классов. Веса компенсируют редкость класса 1.
- На отложенных данных сравнивает время обучения, accuracy, F1 класса 1, precision, recall, ROC-AUC и матрицу ошибок. Простое правило «всегда 0» служит ориентиром.
- Сохраняет прогнозы для 30 282 отложенных договоров в `insclass_validation_predictions.csv`; эти договоры не участвовали в обучении.

Модель вычисляет $p_i=1/(1+e^{-z_i})$, где $z_i=\mathbf{x}_i^T\boldsymbol\beta+b$. Взвешенная кросс-энтропия и логарифмическое правдоподобие отличаются знаком: $J_{LL}=-J_{CE}$. Поэтому при одинаковых настройках градиентный подъём по $J_{LL}$ и спуск по $J_{CE}$ дают одни и те же коэффициенты и прогнозы. Для защиты от переполнения используются `scipy.special.expit` и `numpy.logaddexp`.

## Результаты на отложенных договорах

| Метод | Accuracy | F1 класса 1 | Recall класса 1 | ROC-AUC |
|---|---:|---:|---:|---:|
| Подъём LL | 0,695 | 0,245 | 0,518 | 0,674 |
| Спуск CE | 0,695 | 0,245 | 0,518 | 0,674 |
| Всегда класс 0 | 0,904 | 0 | 0 | 0,500 |

Оба метода дали **точно совпавшие коэффициенты и прогнозы** в проведённом запуске. Время обучения измеряется ноутбуком отдельно для каждого метода и зависит от нагрузки компьютера (при проверке — около 3 секунд на метод).

Из 30 282 отложенных договоров модель правильно классифицировала 21 046. Этот результат рассчитан по строкам из `insclass_train.csv` и служит внутренней оценкой качества, а не прогнозом для отсутствующего файла преподавателя.

Из 2892 рисковых договоров модель нашла 1499 и пропустила 1393. При этом 7843 нерисковых договора были ошибочно помечены рисковыми. Высокая accuracy правила «всегда 0» объясняется сильным дисбалансом классов; его F1 для рискового класса равен нулю. Взвешенная модель повышает полноту обнаружения риска ценой ложных тревог. Порог 0,5 выбран одинаковым для двух методов и не подбирался по отложенной части.

# Текущий контроль 9: нейронная сеть на PyTorch

Подробное решение находится в **[Текущий контроль 9 (реализация).ipynb](Текущий%20контроль%209%20(реализация).ipynb)**. ## Как устроен прямой проход

Нейрон получает признаки $x_1,\ldots,x_d$, умножает их на веса и прибавляет смещение:

$$z=\sum_{j=1}^{d}x_jw_j+b.$$

Несколько нейронов объединяются в слой. Для партии из $N$ объектов с $d$ признаками и слоя из $m$ нейронов формы матриц таковы: $X\in\mathbb{R}^{N\times d}$, $W\in\mathbb{R}^{d\times m}$, $b\in\mathbb{R}^{m}$, $Z=XW+b\in\mathbb{R}^{N\times m}$. В PyTorch операция `@` умножает матрицы, а вектор `b` автоматически прибавляется к каждой строке.

Выход линейного слоя можно пропустить через **ReLU**: $\max(0,z)$. Эта функция сохраняет положительные значения и заменяет отрицательные нулями. Нелинейность необходима: композиция только линейных слоёв всё ещё эквивалентна одному линейному слою и не может описать параболу. Для многоклассовой классификации отдельно показан **softmax**, превращающий логиты в вероятности, сумма которых равна 1. Основная обучаемая задача в ноутбуке — регрессия; на её выходе softmax не применяется.

## Ошибка и обратное распространение

Для регрессии используется среднеквадратичная ошибка $L=\operatorname{mean}(\hat Y-Y)^2$. Её производная по прогнозу при одном выходе на объект равна $2(\hat Y-Y)/N$. Производная говорит, как малое изменение прогноза повлияет на ошибку.

Для слоя $Z=XW+b$ пришедший справа градиент $G_Z=\partial L/\partial Z$ даёт:

$$\frac{\partial L}{\partial W}=X^TG_Z,\qquad
\frac{\partial L}{\partial b}=\sum_i(G_Z)_{i,:},\qquad
\frac{\partial L}{\partial X}=G_ZW^T.$$

Последний градиент нужен предыдущему слою. Для ReLU он дополнительно умножается на индикатор положительного входа. Так работает **правило цепочки**: производные проходят от выхода сети к её началу. После вычисления всех градиентов каждый вес уменьшается на $\eta$ умноженное на соответствующую производную; $\eta$ — скорость обучения.

В ноутбуке классы `Dense`, `ReLU` и `MSELoss` реализуют эти действия вручную. Затем независимый расчёт через `torch.autograd` проверяет четыре группы градиентов: веса и смещения первого и второго слоёв. Эта проверка нужна потому, что сеть иногда способна уменьшать ошибку даже при неточном коде обратного прохода.

## Какие задачи решаются

1. **Линейная зависимость с известными весами.** Данные создаются по формуле $y=2x_1-x_2+0{,}5x_3+3x_4+0{,}7+\varepsilon$. Один нейрон обучается стохастическим градиентным спуском: после каждого отдельного объекта выполняется обновление. Найденные веса можно сравнить с настоящими.
2. **Нелинейная зависимость.** Данные приближают $y=x^2+\varepsilon$. Один линейный нейрон сравнивается с сетью `Dense(1,16) → ReLU → Dense(16,1)`. Обе модели обучаются на одних и тех же 120 объектах и проверяются на одинаковых 40 отложенных объектах. Графики показывают форму прогнозов и изменение MSE. Обучение здесь использует всю обучающую часть на каждом шаге — это полный градиентный спуск.

**Epoch** означает один проход по всем обучающим объектам. При SGD с партией размера 1 за эпоху делается столько обновлений, сколько объектов. При полном градиентном спуске за эпоху выполняется одно обновление. Разницу важно учитывать, сравнивая графики и время обучения.

## Как читать результаты

Низкая ошибка на обучении показывает, что модель подстроилась под увиденные примеры. Ошибка на отложенных данных показывает, насколько хорошо она работает на новых объектах той же синтетической задачи. Шум в данных не позволяет ожидать ровно нулевую ошибку.

При проверке все четыре группы ручных градиентов (`W1`, `b1`, `W2`, `b2`) **точно совпали** с результатом `autograd` в пределах `float32`. На линейной задаче SGD нашёл веса примерно $(2{,}002,-0{,}999,0{,}501,3{,}000)$ и смещение $0{,}704$ при истинных $(2,-1,0{,}5,3)$ и $0{,}7$; MSE на отложенных данных равна **0,00218**. Это показывает, что один нейрон действительно восстановил заданную линейную зависимость.

На параболе линейный нейрон проводит почти горизонтальную прямую. Сеть с ReLU строит приближение кривой из нескольких отрезков. Численные результаты на **одних и тех же 40 отложенных объектах**:

| Модель | MSE на обучении | MSE на проверке |
|---|---:|---:|
| Один линейный нейрон | 0,09600 | 0,09107 |
| Сеть 1–16–1 с ReLU | 0,00404 | 0,00529 |

Проверочная ошибка сети примерно в 17 раз ниже. Это не доказывает, что нейросеть всегда лучше: специально выбрана нелинейная зависимость $x^2$, которую прямая не может описать. Если данные линейные, один нейрон проще и достаточен.
